# 行情缓存复用与定期维护

## 任务边界

本任务交付整组设计蓝图、共同契约、阶段安排，以及 current spec 的整体整理。共同算法与错误约束见 [spec_01_contract.md](spec_01_contract.md)。主任务和各功能任务分别维护 meta、context、spec；正式规范独立自述，不依赖外部讨论材料。

允许改变：CCXT 三种 OHLCV 的明确查询流程与尾根确认；TQ 普通行情接入磁盘缓存并退出多合约输入；日历和历史映射改走自有源；新增节点过渡、缓存概况、保留清理和后台 HTTP 计划。

保持：原缓存时间戳重叠、片段与覆盖证明、有效修订和事务；未明确改变的鉴权、模式、交易所能力、预算和错误；Kraken Spot 现状；TQ Tick 与交易状态原有职责。CFB、CTP、交易价格及下单路由不作业务变更。

不增加分布式系统、另一套缓存、通用 Provider 框架、逐级行情试探、全历史镜像、自动整库重建或强制刷新参数。全局／数据源／品种的多层保留覆盖不纳入本轮，公开配置只采用环境保留值。

项目重点维护上市后的正常数据。上市前相关请求，现有链路能直接处理就处理，处理不了就明确拒绝；不新增上市日期查询、历史起点探测或跨空窗口补拉，不把“上市历史不足必须成功”作为跨数据源承诺。正常取得的合法短结果仍按各查询契约返回，不能把网络失败或未到目标边界伪装成短成功。

主任务的 current spec 整理覆盖整个目录：

- architecture 明确调用链、资源所有权和模块边界。
- 缓存三篇区分存储证明、公开操作与 CCXT 查询编排；共同术语集中说明。
- CCXT 与 TQ 规范准确列出现行路由、单位、输入与结果资格，不把两类获取算法混为一谈。
- configuration、system_time、verification 明确配置、取时与验证职责；其他模块核对交叉引用和共同约束，不重写独立业务。
- 新增 market_data_contract.md 说明现行的数据证据与职责；具体算法仍由各主题唯一维护。

主任务只将已经成立的规则写入 current spec。未来 API、TQ 缓存与后台配置在本组 task spec 冻结；各功能实现阶段同步对应 current spec、OpenAPI、Bruno 和必要用户入口。不得将未实现设计先写成现行功能，也不将实现缺陷静默改写成规范。

停止线：共同契约、接口作用域、阶段交接和验证责任完整；每个阶段能独立指导实现；现行规范与源码能力边界一致。没有代码授权时，不生成运行配置、不修改源码或测试、不执行验证命令。

## 任务规范

### 共同所有权

正式数据链为业务获取与批次校验 → 缓存高级 API → 业务结果组织与最终校验。路由、脚本和元数据模块不得操作底层连接、SQL、segment_id 或覆盖元数据。

业务层提供来源、完整批次和尾根资格；缓存内部筛选持久化行、连接片段、更新修订与元数据。普通片段合并和过渡整窗提交共享尾根筛选，但不能混用提交语义。

缓存资源由应用生命周期统一持有，CCXT、TQ 和维护复用；关闭单个 Provider 不能提前关闭共享库。网络等待不占数据库写锁。元数据下载不进入行情 SDK 工作线程。

CCXT 对外保持毫秒，TQ 对外保持整数纳秒；日历与映射日期保留中国期货日期含义。跨源全局排序必须统一时间基准，不能直接比较毫秒与纳秒原始整数，也不能损失 TQ 精度或收窄 CCXT 已有合法时间范围。

### 阶段职责与交接

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 共享缓存基础 | 生命周期、高级普通行情 API、TQ 字段承载、schema 升级机制 | 原 CCXT 查询不变，旧数据保留，读取与关闭一致 |
| CCXT 查询统一 | 三个查询共享前缀与向后分页，取消专门确认，固定 S | 含首连接、正常短页续取、边界明确结束、预算及最终校验通过 |
| TQ 普通行情 | 单合约固定 SDK 窗口、缓存补充、失败后状态分支 | 可复用超过一万根历史，休市与未知状态分清 |
| 日历和映射 | 自有源、在线核验、日期片段、真实节点、旧 SDK 硬禁 | 两条元数据路由同时切换且保持可用 |
| 过渡窗口 | 单次目标 N＋1 证明、整窗持久化、可变长度 | 长窗口不被短请求覆盖，旧合约筛选数据不批量入库 |
| 概况和保留 | 只读统计、按环境/年份清理、元数据原子维护 | 所有新增数据类型均能正确清理和并发读取 |
| 后台调度 | 公开计划、私有 HTTP 账号引用、采集后清理 | 服务可访问后首轮、关闭收尾、不重入、错误继续 |
| 集成验证 | 跨模块与用户入口核对、最终手动在线验证 | 整组功能契约与 current spec 一致，无未承接必测项 |

采用线性 JJ 栈承载阶段，功能依赖仍以职责为准；CCXT 与 TQ 获取算法互不调用。主任务不通过未来任务文档解释自身契约；后续任务可以引用本任务及已有前置。

缓存基础阶段不提前实现所有辅助业务。日历／映射阶段扩展其类型化缓存接口，过渡阶段扩展完整窗口接口，维护阶段覆盖已经存在的数据类型；它们继续在同一个缓存模块内实现，不能创建各自的片段管理器。

### 迁移约束

- 共享所有权调整必须同时更新生产生命周期、直接构造 Manager 的测试和必要调试调用方。
- CCXT 查询替换在同一阶段完成；普通 lookahead、项目倒序取数及结束时间参数分支退出，含首连接所需重叠行保留。
- TQ OHLCV 单合约在行情阶段生效；映射单合约及旧 n 参数在元数据阶段生效；各中间 revision 的文档准确描述当时能力。
- 自有元数据两条链与旧 SDK 禁用同阶段交付，不保留兼容回退；过渡尚未交付时不提前接受其参数。
- 后台配置模型、默认公开文件、账号引用、脚本与生命周期同阶段启用。默认测试配置显式关闭自动调度，不能启动真实小时任务。
- 每阶段调整对应旧测试与用户示例，不以最终集成任务兜底阶段性测试失败。

## 公开接口与用户写法

### 最终接口范围

| 入口 | 最终用户契约 |
| --- | --- |
| CCXT 三种 fetch_ohlcv | 保留 URI、参数、live 默认及 rows/completion 包装；固定周期 latest-limit 新增缓存复用 |
| /tq/fetch_ohlcv | 单 symbol；data_length 默认一万、范围 1..100000，表示最多返回数量；SDK 请求 min(N,10000)；enable_cache 默认 true |
| /tq/fetch_tick | 原接口保持，无项目磁盘缓存 |
| /tq/fetch_underlying_symbol | 单 symbol；保留 items；历史改用成对 start_time/end_time 整数 Unix 纳秒；旧 n 拒绝；history 返回真实节点 |
| 同一映射入口的过渡 | transition_timeframe 可选，transition_bars 默认 10、1..9999；不传周期省略 transition |
| /tq/fetch_trading_calendar | 保留 start_date/end_date 自然日闭区间；增加默认 true 的 enable_cache |
| GET /cache/summary | 本地实际片段概况，不触发 SDK 或源刷新；不宣称固定保留 K |
| POST /cache/prune | 调用方显式提交 providers、modes、可选 auxiliary；回显本次规则与各部分结果 |

TQ 普通 records 包装保持，不附加 CCXT completion 字段。日历和历史映射不接受 refresh_source；映射无论是否带历史范围都在线重新取得官方历史源，items 与 history 使用同一来源。

历史映射最多返回和持久化到本次实际行情支持的生效交易日 D，超出该日的历史请求明确拒绝。items 取官方事件源在 D 上生效的合约；未来事件不进入 items、history 或日映射缓存。SDK 当前标的查询及其业务回退退出；日历的官方未来日期能力不因此收窄。

只传一端历史时间、时间倒置、非法周期、未知参数及多值 symbol 在获取或缓存前拒绝。transition_timeframe 需要历史范围；单独 transition_bars 不启用过渡。日期范围转换由服务端处理，脚本不能将夜盘时间简单取自然日期。

真实主链写法：

```text
GET /tq/fetch_ohlcv?symbol=KQ.m@SHFE.rb&duration_seconds=300&data_length=20000&enable_cache=true
GET /tq/fetch_underlying_symbol?symbol=KQ.m@SHFE.rb&start_time=1790125200000000000&end_time=1790211600000000000&transition_timeframe=5m
GET /tq/fetch_trading_calendar?start_date=2026-09-01&end_date=2026-09-30&enable_cache=true
GET /cache/summary?provider=tq&symbol=KQ.m@SHFE.rb
```

以上请求均使用既有 Bearer 鉴权。所有普通网络 OHLCV 响应保留目标尾根，持久化规则见共同契约。

### 周期范围

重点维护周线及以下。CCXT 完整查询支持的固定周期使用统一分页与缓存；周线以上仅 SinceLimit/LatestLimit 单页薄转发，limit 不超过该 Provider 单页限制，不使用缓存，SinceLatest 返回 NOT_SUPPORTED。Provider 未声明周期时仍拒绝；Kraken Spot 原能力不变。

TQ 大于一周的周期保持既有 duration_seconds 合法性，普通行情只作 SDK 单窗口薄转发，不读写项目缓存、不作休市缓存兜底；大周期过渡只有起点与目标窗口可以证明时才返回。月不按固定三十天解释。

### 后台用户配置

公开 market_data.toml 只控制后台计划；私有 config.toml 的 market_data_client 引用 users 中已有 HTTP 账号。完整逐参数注释的示例由后台阶段正式规范冻结，不能从运行代码反推默认值。

默认 28 个品种、5m/1h/1d/1w、主连与加权每次一万根；mapping_timeframes=["5m"] 只从 5m 主连响应触发映射，transition_timeframes=["5m"] 附带 5m 过渡，1h/1d/1w 默认只采集行情。日历取十年；每小时依次采集和清理。live 每序列三万、sandbox 零，辅助数据十年。脚本不跳过鉴权、不直调业务函数、不直接打开数据库。

这些开关与依赖属于脚本：save_mapping 依赖 save_main，启用时 mapping_timeframes 非空且属于 timeframes；save_transition 依赖 save_mapping，启用时 transition_timeframes 非空且属于 mapping_timeframes。映射本身仍是逐交易日数据，这两个列表只控制后台触发。用户独立调用路由不受这些依赖、后台清单或开关限制。

## 测试、验证与阶段过渡

本主任务文档阶段只核对文本、引用、示例、行数和版本差异，不运行构建、lint、类型检查或测试。每篇手写文档不超过 400 行，meta 不超过 60 行；正式文档不维护执行日志或进度表。

所有代码阶段必须将对应离线回归纳入并通过 just test；同时使用现有只读静态检查入口 just lint、just check。变更导致的旧断言在该阶段更新，不删除仍有效的反向约束。测试、静态检查的实际运行仅在后续代码授权下进行。

共同必测：原片段连接/覆盖/修订不变量；网络与缓存尾根区别；纯网络、纯缓存及合并校验；固定 S 与含首连接；TQ 不使用 interval；身份/单位隔离；输入拒绝先于副作用；失败不制造成功或假连续；默认开启与显式关闭缓存。

历史边界验证只证明正常链路能直接返回合法数据，或不能完成时明确结束；不要求测试驱动新增上市前搜索。元数据验证覆盖 SDK 当前标的入口硬禁、每请求重新获取事件源、摘要/完整内容命中与历史修订、D 之后不能形成历史覆盖，以及默认只有 5m 触发后台映射。

每阶段同步维护其离线 fixture、OpenAPI/Bruno 契约和 current spec；需要移除的旧 API、类型、测试、调试入口和描述必须列入相应阶段，不建立长期兼容包装。

最终集成承担共享库、维护、网络获取、后台 HTTP、自有源和关闭交互；包括仅 TQ、仅 CCXT、混合启用、服务禁用、初始化失败、重复关闭、写入与清理竞争、重启续接和无法重叠。

just test-online 保持与离线入口分离，只在整个实现和离线验证结束后手动运行一次。只取 live 公共行情和 TQ 数据，写入隔离测试缓存；不下单、不请求私有账户、不调用实际运行库清理、不启动生产后台计划。上游失败或缺少身份如实报告，不以 sandbox 或无限重试替代。
