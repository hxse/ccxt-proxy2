# 共同数据证据、查询与缓存契约

本篇定义整组任务唯一的共同规则。各功能任务只展开其专属接口和算法，不另立连续性、尾根、时钟或缓存错误机制。

## 历史边界的维护取舍

项目重点维护上市后的正常数据。上市前相关请求，现有链路能直接处理就处理，处理不了就明确拒绝。正常取得合法短数据按接口契约返回；不新增上市日期查询、历史起点探测、跨空窗口推进或专项恢复算法。

这一原则适用于 Binance、Kraken 和 TQ，不把某个 Provider 能直接返回短历史扩大成全项目保证。边界必须属于请求的实际数据序列，不能用当前实际合约上市日截断整条主连历史。现有 covered_from 和顺带取得的空白前缀证明保留，不为扩大它额外请求；空结果不创建空片段。

## 数据身份与证据

普通 OHLCV 身份包含 provider、mode、market、symbol、timeframe、variant，所有影响价格的数据维度必须隔离。TQ 主连、加权、实际合约是不同 symbol；复权参数属于身份。日历、日映射、过渡各有类型化身份，不把辅助数据塞入 OHLCV 六列。

segment_id 标识已成立的连续关系，不表示时间顺序或一次请求。有效批次可以经真实时间戳交集连接；时间范围相交、固定时间差或相邻日期不能代替交集。无实际交集继续分段，读取不跨片段凑数。

covered_from 表示已证明的查询下界，允许早于 first_time；只有遵循 since 的权威请求才能提供空白前缀证明。仅请求最新数量而没有 since 的 SDK 窗口没有这一证据。删除片段前缀后，覆盖下界必须重置为新的实际首行。

官方批次完整性分别验证：CCXT 支持域检查固定 interval 和分页重叠；TQ 使用稳定的单合约 SDK 序列和原生 id 顺序；日历检查全部自然日；映射检查有效交易日并保留真实节点上下文；过渡检查同次结果的正确起点及 N＋1 根。

先验证输入批次，再交缓存 API；最终响应再按类型验证，覆盖网络、缓存和合并结果。缓存内部仍保护结构、事务和证明不变量。TQ 原有合法 nullable 字段保持其响应语义；不能以删掉中间坏行建立片段。可持久化普通 OHLCV 行必须满足缓存的完整价格/数量契约，整批资格不成立则不写，不能只存其中好行。

## 持久化与响应尾根

普通网络 OHLCV 不再专门多请求后继。完整查询完成并按本次边界裁剪后，将网络目标批次末根标为无法确认，完整交给缓存；缓存内部排除它的新增持久化，响应仍保留目标尾根。

多页查询只排除完整网络结果的最后一根，不逐页去尾。缓存读取出来的行已可信，不重复去尾，也不因读取而重复写回。未知网络尾根若已在库中，不删除或降级旧缓存，不用未确认新值覆盖它。

普通片段的已有有效行按新批次整行更新；网络缺少旧时间戳不表示删除。不新增无变化比较器或“无新时间戳就跳过”逻辑，避免丢失桥接、修订和覆盖扩展。现有 upsert 可以产生重复物理写入，本任务不承诺零写入优化。

CCXT 保留 last_bar_completion_confirmed：非空纯可信缓存 true，未确认网络尾根 false，空结果 null。TQ 保留 records 响应，不新增此包装。合法短响应不因没有凑够请求量而报错。

过渡目标 N 默认 10。外层提交同一次稳定结果的目标 N＋1 根并标记末根未知；缓存用同一尾根筛选得到 N 根，再原子整窗提交。返回前 N 根；不足 N＋1 时返回本次可靠数据最多 N 根但完全不写过渡缓存。已确认 K 根可以读前缀，不能与网络拼成扩大窗口；较短并发提交不得缩短 K。

## CCXT 唯一分页与快照

项目分页只调用 exchange.fetch_ohlcv(symbol, timeframe, since=cursor, limit=page_size, params=variant_params)。Provider 内部适配原生 HTTP 参数属于 SDK；项目不再构造 until、to、endTime 等终点分支，不使用 automatic pagination。

需要最新边界时，先通过同一方法的 since=None、limit=1 特例得到 S，只取一次。后续页、缓存候选和最终结果都裁去 S 之后的数据；这些行也不参与写入或完成证明。冻结时间戳，后取得的同时间有效价格仍可修订响应。

SinceLimit 不为统一而额外取 S。SinceLatest 与 LatestLimit 共用接受既定 S 的内部查询；LatestLimit 固定周期按 start=S−(N−1)×interval 计算起点。区间只作本地约束，不传 SDK 起止区间。

前缀不足时从真实缓存末端含首补拉；连接失败放弃整个前缀，从原始起点完整重拉一次。进入网络阶段后不搜第二段缓存。分页从真实末端继续，不用 tail＋interval；保留重叠容量、单页限制、无进展和溢出检查。

固定周期必须校验最终时间顺序、间隔、数量与边界。非空短页只要有合法进展，就沿真实末根含首继续正常分页，短页本身既不是完成证据也不是错误。快照查询起点不晚于 S 时必须实际到达 S；空页、无进展、缺连接点或内部缺口按查询契约结束或报错，不跨空窗口搜索。正常链路自然取得并完成目标语义的合法短历史可返回，不承诺自动恢复上市前边界。完整操作失败不返回或缓存部分页。

## TQ 普通行情

单 symbol；项目只用最新窗口模式。请求 N 根即调用 SDK min(N,10000)，固定本次结果副本。不做时间游标、interval 连续性推算、窗口阶梯试探或数量达标循环。

成功结果按共同规则缓存；达到 N 时直接组织 SDK 响应，不为返回内容重复读库；不足时由高级 API 读取与本次窗口具有原片段连接证明的历史，最多返回 N 根。不把孤立尾根追加到任意旧片段。

先请求 SDK，成功不查询交易状态。仅可归类为网络/服务失败且缓存启用时，取得可靠实际合约并读一次既有状态快照；只在 raw_status=NOTRADING 且 is_open=false 时返回最新连续缓存。集合竞价、未知、权限不足、断线或状态查询失败不能成功兜底。非法请求和非法数据不进入该分支。

实际合约直接检查自身；主连和加权通过统一历史映射入口取得主连在参考交易日的实际合约。元数据阶段替换前置行情阶段的 SDK 当前标的解析，不保留旧回退。解析不可靠时明确失败，不使用过期映射替代。不能以本机时段、日历或无新数据判断休市。

缓存关闭时禁止项目读写和休市兜底；SDK 自身内存缓存不受开关控制。正常 SDK 结果可能来自已订阅 serial，不宣称每次 HTTP 都重新下载数据。

## 日历与映射源

两个元数据业务入口统一先取得服务端可信在线时间；映射还取得同一主连最新一根 5m K 线的时间。仅当前 items 与显式历史范围都走这一链路。每个 HTTP 操作固定一次时间，转换为 Asia/Shanghai；转换核心只接受显式边界与稳定源快照，不读本机当前日期。

复用 /system/fetch_time 背后的公共函数。脚本取得的时间仅用于构造请求范围，服务不信任客户端传入的“当前日期”，不增加时间票据协议或跨请求 TTL。公共时间失败不回退本机。

日历以已校验官方节假日列表的实际最大日期 H 判定：可信自然日 C≥H 或尚无可靠 H 时取得新源；C<H 且缓存覆盖足够可复用。缺失范围也取源。H 不硬编码成年末，不混同官方日历有效年份或响应末日。

每操作最多一轮源刷新。刷新后 H 未延长不循环；请求范围仍有效可返回，否则报错。后续请求仍可重新触发，不暗加小时 TTL。

映射以稳定参考行情时间确定实际生效交易日 D，不从当前时钟的周末/夜盘日期推算结果直接指定 D。在线时间用于本次可信检查；参考行情为空或非法时明确失败，不通过 SDK 当前标的补救，也不从价格猜合约。

每次映射请求重新下载官方事件源，仅合并同源在途下载。当前 items、历史 history 和休市兜底的合约解析都以该源为唯一依据，U 从源在 D 的有效节点派生；删除与 SDK 当前标的相等的检查。历史源末事件日不用于判定过期，D 之后事件不进入当前结果或历史缓存。重新下载不承诺官方自身无发布延迟。

缓存高级接口检查源摘要、请求覆盖和本次有效日表/节点的一致性；完整命中不重复写回，否则按原有事务与片段机制保存。全局源摘要已更新不能替另一片段的旧内容背书。下载或转换失败明确报错，不能用缓存掩盖失败。

日历按 date/trading 完整自然日保存；映射逐有效交易日保存。均使用 segment_id 和实际日期重叠。映射从连续日序列识别第一个新合约，保留真实节点及不同前驱合约；查询从合约中途开始也返回其真实生效节点，不伪造查询起点为换月日。

原 SDK get_trading_calendar、query_his_cont_quotes、query_symbol_info 在生产适配实例硬禁，自有入口不得转调；第一方业务也禁止直接 get_quote/query_graphql 获取当前映射。SDK 内部为行情加载基础合约信息不作为项目映射来源。静态架构检查与运行时反向用例共同约束，离线参考白名单仅允许旧日期转换，不放行当前映射旁路。

## 保留、统计与维护

普通 OHLCV 每条完整序列跨所有片段按时间保留最新 K，live 默认三万、sandbox 零；TQ 属于 live。清理扫描目标类别的全库序列，不限后台清单，不合并独立片段，不要求保留下来的 K 根整体连续。

辅助数据默认十年：日历删旧日期；日映射保留左边界必要节点与前驱；过渡按实际 K 整窗保留/删除。它们不依赖对应普通行情是否存在，不因行情清理被级联删除。

现有写入容量保护、周期保留与响应预算独立。两轮清理间允许超过周期 K。原写入大容量保护仍覆盖普通行情，不能把两百万/两千万直接改成三万/零。

概况只报告实际数据：最新连续片段的 start/end/count、总行数、片段数量与身份；start 不是 covered_from。空序列为 null/null/0，不返回 segment_id，不宣称一个固定的“生效保留 K”。K 在本次清理请求与响应中表达。

数据库所属进程执行维护，网络在锁外，每条序列的删除和证明更新原子完成，清理不重入。物理空间回收交给 DuckDB 正常 WAL/checkpoint；不承诺删除即缩小文件，不每小时复制重建整个库。容量估算仅是预算。

## 错误与后台

普通缓存读失败 warning 后按 miss 处理；有完整网络成功结果时，普通写失败记录 error 仍可返回网络结果。原容量处理失败回滚并返回 507 CACHE_CAPACITY_EXCEEDED。没有成功网络结果的休市兜底若读库失败，必须报错。

日期/映射源刷新失败不能回退旧 SDK 或旧缓存冒充成功。保留已存在可信历史，不推进失败操作的源核验事实。有效来源取得成功但普通持久化失败时，按缓存错误契约返回已验证来源，不能虚报写库成功。

后台仅通过 HTTP 鉴权调用同一路由，采集与清理两个单轮脚本由一个小时流程顺序执行。错误按项目与部分记录，继续独立工作；取时失败不阻断普通行情和按根数维护。上一轮未结束跳过触发，不积压。

默认四个周期都采集主连/加权，但只在 mapping_timeframes=["5m"] 的主连响应后请求映射，并按 transition_timeframes=["5m"] 附带过渡。时间按业务请求各取一次并在内部固定；采集和清理不共享整轮可信日期，嵌套转换/刷新也不能在同一请求中重新取时移动边界。

应用必须先提供可用 HTTP 再发首轮请求，不能在 lifespan 启动完成前等待本机接口。关闭先停止调度和新工作，处理在途请求，再关闭 SDK 与共享缓存。请求超时不等于底层 SDK 已被取消，不允许遗留无法收尾的任务。
