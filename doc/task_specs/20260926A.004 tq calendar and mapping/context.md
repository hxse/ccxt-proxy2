# TQ 日历与主连映射迁移

## 使用场景与设计初衷

SDK 日历把节假日表保存在模块变量，历史主连表保存在类变量，首次获取后不自动重下载。长期服务即使每小时请求，也可能重复展开旧表；最近 n 个交易日还依赖 SDK 当前时间。

用户需要明确范围、可靠覆盖与自动刷新，并让映射对外只返回实际换月节点。节点首日和旧合约必须来自历史上下文，不能把截取后第一行当作换月。

官方事件表可能提前公布下一交易日的切换，此时最近实际行情仍属于此前交易日，当前标的也尚未切换。预公告不是任意未来预测，更不能用其日期替代当前核验日。历史查询需要以实际行情所支持的已生效日期为上界。

SDK 当前合约资料的交易日可能正确，但 underlying 仍指向旧合约；行情价格和历史事件已经换月时，两源核对会拒绝本来可用的历史数据。Quote 的标的字段仍来自相同合约资料，换一个 SDK 方法不能形成独立证明。

## 方案对比

清空 SDK 全局变量后重调原方法会影响其他能力，也保留了隐式时间和两套入口。提取必要的官方转换，项目自己下载源表、注入日期并禁止旧调用，更便于维护和验证。

以官方历史事件为唯一依据，并在每次请求重新取得源，能移除失真的当前标的依赖。接受官方自身发布时效，不用价格反推合约；不维护平行映射或通过旧入口兜底。

date 唯一键能去重，不能独立证明区间完整。自然日枚举可验证日历，日历确定的交易日集合可验证映射；有效批次随后复用现有 segment 机制。

## 取舍结论

两条元数据路由在同一阶段切换，自有源与缓存各守职责。日历使用真实源末日期与覆盖检查；映射每请求重新获取官方历史源，以参考行情日期限定生效边界，不引入 TTL、强刷参数或本机时间回退。当前标的与历史统一来源。

前置空白只做下载结果内的简单裁剪；无法确认更早节点则依既定错误/空前驱语义结束，不查询上市日期或额外寻找上市前历史。预公布但未生效事件只留在源快照，不当作日映射缓存。
