# TQ 普通行情接入缓存

## 使用场景与设计初衷

SDK 单窗口最多一万根，本地缓存可以通过普通用户请求与后台请求自然积累更长历史。用户需要按请求返回最多 N 根连续数据，包括不一定能够持久化的最新尾根。

SDK 自身会复用 serial，因此正常返回不应先被休市判断否定。只有获取失败时，真实状态才能决定是否允许读历史缓存。

## 方案对比

按时段或 interval 推算缺口无法正确处理休盘与节假日。逐级扩大窗口又与 SDK 自带缓存重复。一次取得 min(N,10000)，由既有片段机制补充历史，流程最直接。

缓存读出的末行已经可信，再砍一次会损失有效数据；将网络未知尾根单独接到任意历史则会制造连续性。两者必须在数据来源边界区分。

## 取舍结论

获取算法独立维护，只扩展共享缓存的调用；单合约、固定窗口、两处校验、明确失败分支。允许正常短响应与无法重叠的独立片段，不追求强行凑足 N。
