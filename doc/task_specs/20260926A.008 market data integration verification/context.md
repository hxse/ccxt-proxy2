# 行情缓存集成验证与规范核对

## 使用场景与设计初衷

各功能阶段分别验证了算法和接口，仍需证明用户请求、后台 HTTP、元数据下载、SDK 单线程和共享数据库在同一应用中不会互相破坏。测试通过单个函数不能代替启动、关闭和并发交互。

接口和配置经历明确迁移后，OpenAPI、Bruno、默认测试隔离及 current spec 也必须一致，否则旧用法仍可能被推荐或默认测试意外启动真实后台。

## 方案对比

把所有测试留到最后会让中间任务不可交付；各阶段必须先通过自己的离线验证。本阶段仅承担尚未覆盖的交互与整体一致性，并使用最终一次手动在线查询检验真实依赖。

只在真实服务反复试验难以复现竞争，也可能污染生产缓存。主要证据使用确定性离线 fixture、临时 DuckDB 与本地 HTTP 替身；在线只确认 live 只读链可用。

## 取舍结论

以用户可观察结果和证明不变量为准，不追求测试数量或重复跑网络。外部条件不足如实报告，不能把 skip 当成已验收。
