# 行情缓存集成验证与规范核对

## 任务边界

整组行为以[主任务](<../20260926A market data caching and maintenance/spec.md>)与各前置正式 spec 为准。本任务补齐跨模块集成验证、旧用法退出检查和最终文档核对，不重新设计查询或缓存算法。

前置任务必须已通过其必需验证；不得接收笼统的“以后补测试”遗留。范围内机械适配和已冻结契约缺陷可以修复，若发现需要改变核心设计或修复其他任务所有权，按项目规则先明确范围。

无新的业务 HTTP、配置键或缓存 API。停止线是下述跨阶段场景通过，公开契约/规范一致，最终在线实际结果和未覆盖项可明确报告。验证记录只在交付回复中报告，不写 execution/review 文件或 task 进度表。

## 任务规范

### 集成环境

离线默认不访问真实交易所、TQ、公共取时、源文件或私有运行配置。使用固定源快照、受限 SDK 替身、mock HTTP 或本地 ASGI、独立临时 DuckDB；应用配置隔离在测试收集和模块导入前生效。

自动后台默认在测试中关闭，只有专门调度场景注入启用的测试计划。不能等应用已启动后再由普通 fixture 关闭它，也不能临时修改项目根 market_data.toml 或用户 config.toml。

模拟不同线程/请求时使用可控屏障和小样本，不靠长 sleep 概率复现。观察实际返回、数据库数据与片段不变量，不只断言 mock 调用本身。

### 跨模块场景

| 场景 | 必须证明 |
| --- | --- |
| 仅 TQ、仅 CCXT、混合启用 | 同一应用拥有共享库，未启用 Provider 不被维护/概况隐式启动 |
| 启动失败、取消、重复关闭和重启 | 已创建资源释放，旧客户端不能重开关闭的库，后台先停再关闭共享资源 |
| 用户与后台请求同一 TQ 序列 | 同样输入产生同样缓存语义；后台无第二套保存/删尾流程 |
| 普通写入、整窗替换和清理并发 | 同一锁域、事务可见性和正确元数据，不混合半个窗口 |
| SDK 数据与历史缓存连接 | 停机后可重叠自然续接；不可重叠继续分段，不跨午休/周末用 interval 拼造 |
| 可信时间和元数据源失败 | 不回退本机/旧 SDK，不推进核验事实；普通行情和根数维护按契约仍可执行 |
| 清理与业务响应竞争 | 周期保留不缩短已成功网络响应，可信缓存末根不再删尾，查询快照一致 |
| CCXT 分页期间新增行情 | 所有结果保持首次 S，价格修订仍按同时间覆盖；不存在项目终点参数 |
| CCXT 正常短页与过早起点 | 有进展的短页沿真实末根继续；已知 S 却遇空窗明确失败，不新增上市前搜索 |
| TQ 预公布未来事件 | D 只由参考行情时间确定，U 从每次重取的历史源派生；预公告不延长历史覆盖、不触发过渡，超 D 请求/提交明确拒绝 |
| 纳秒与毫秒共享全库 | 时间排序正确，身份和原生精度保持，不因单位数量级错误淘汰 CCXT |
| 过渡与映射修订 | 完整身份区分新旧窗口，N 不分裂身份，5→3→10 和短请求迟到不缩短 K |
| 配置开关与用户调用 | 后台关闭/改清单不限制用户日历、映射、过渡或清理 |
| 后台默认映射触发周期 | 四周期采集行情，仅 5m 触发映射/过渡；5m 失败不借其他周期补发 |
| 取时作用域与概况 | 每个元数据/年限维护请求各取一次、内部复用；概况只报实际存量，K 只随本次清理回显 |
| 自动首轮与 shutdown | HTTP 可用后登录请求，无 lifespan 自调用死锁，无遗留请求或重复调度 |

同时覆盖 schema 1→当前版本的整体升级、失败回滚、保留旧 CCXT rows/覆盖、重启后读取新辅助表。不能只证明各单步升级而漏掉从真实旧库直接升级的链路。

还须覆盖已生成但缺少逐日 roll_date 关联的 schema 3/4，明确升级到 schema 5；不能只检查版本号或只测试新建空库。升级保留所有已存数据及片段，旧映射关联无法证明时暂按 miss，待正常官方获取原子补齐；清理保留该阶段必要上下文，不推算或伪造节点。事务失败必须恢复原结构与版本，已有正确关联不能退回未证明状态。

先保存日历、映射和过渡，再执行普通 OHLCV 写入及容量淘汰，断言辅助片段不被原全库元数据刷新误删。不同数据类型复用片段规则，不等于可用同一张行表判断所有片段是否为空。

### 旧契约退出

检查生产、请求/响应类型、Bruno、debug、示例和测试：普通后继确认、项目倒序参数分支、TQ 多 symbol、映射 n、refresh_source、原 SDK 日历/历史/当前标的入口及 Quote/GraphQL 映射旁路、脚本 SQL/SDK、后台强刷/试探/达标循环全部按所属阶段退出。

上市前不是重点维护场景。不得为满足“所有上市前请求都成功”的旧期望增加上市日期依赖、跨空窗口推进或历史起点探测；已有可靠 covered_from 与正常取得的合法短结果继续验证。Kraken mock 反映真实 SDK 的有限时间窗口，不用简单的 since 后 N 行替身掩盖短页行为。

保留原来有独立作用的含首重叠、溢出检查、缓存可信尾根、Kraken Spot、Tick、状态断线失效和交易模块。禁止用大范围删除测试或额外兼容包装让迁移表面通过。

现有仓库文档行数检查仍使用旧 docs 目录和 500 行阈值时，在本任务改为检查受控正式 Markdown 的实际目录与 400 行、meta 60 行；AGENTS.md、明确生成/第三方内容按既有豁免处理，不纳入外部未跟踪材料。检查不得成为空扫描成功。

### current spec 整体核对

核对目录内全部规范，重点为共同数据契约、架构和所有权、缓存存储/API/查询、CCXT/TQ、元数据、过渡、维护、后台配置、公共时间与验证。每个规则有唯一详细定义，其余引用；不保留过期字段、单位或能力表。

新能力只在对应实现已经完成后写成现行行为。CFB、CTP、Telegram 独立业务保持，必要交叉引用一致；不能为格式统一删除其有效规范。复杂主题按职责拆分并保持每篇不超过 400 行。

核对根用户入口、公开配置注释、私有示例账号引用、容器端口/挂载、单轮 CLI 和 OpenAPI/Bruno 的真实字段；不能只验证规范之间自洽而不对应代码。

重点核对 mapping_timeframes=["5m"]、transition_timeframes 为其子集，以及默认 1h/1d/1w 不请求映射。分别检查范围内的真实日映射、仅在源中的未生效预公告和合法未来日历，不能用同一个“未来”判断混淆三者。

磁盘描述区分逻辑行数、数据库文件与空闲预留。默认 28×4×2×30000=6720000 根是全满估算，日历/映射/过渡不作为额外整套行情重复计算；索引和压缩未实测时不得把预算宣称为占用或硬上限。

## 公开接口与用户写法

不新增业务用户写法；以下为验证入口，必须保持离线和在线分离：

```bash
just test
just lint
just check
```

上述通过且整组实现完成后，手动执行一次：

```bash
just test-online
```

默认 just test 继续显式排除 Test/online。在线聚合仅使用 whitelist 的 live 公共 CCXT 数据及 TQ 数据，临时缓存与生产库隔离；不调用任何交易/账户/Telegram 写操作，不调用生产 prune，不自动启动完整 28 品种后台采集。

TQ 数据不接受 sandbox 参数。CCXT 不因缺少 live 身份改用 sandbox；无配置/无权限/网络不可用如实标明，不能把全部 skip 记为在线通过。

在线最小覆盖三种 CCXT OHLCV、一个 TQ 主连/加权窗口、缓存响应尾根、自有日历/节点和一个可用过渡场景；另以沥青验证不带范围与带范围都成功、当前与历史合约一致，关闭缓存时不落日映射。过渡若源窗口确实无法覆盖，报告该限制，不靠反复请求寻找成功样本或旧 SDK 回退。

## 测试、验证与阶段过渡

本任务文档阶段不运行上述命令，只检查文档。后续实现验证按顺序运行 just test、just lint、just check，再运行最终一次 just test-online；代码变化期间不同时执行正式验证。

离线正向证明合法输入成功，反向断言准确类型、阶段与必要上下文；容量/源格式/禁用入口/状态未知不能用任意异常替代。核查 warning、异常跳过和测试 summary，不只看退出码。

在线设有限等待与有限重试，显著异常或反复失败停止相关在线工作并报告；不机械循环直到通过。单次在线失败仍是未验证/失败，不临时修改 spec 降低要求。因明确缺少外部前提不能完成的部分与已验证部分分开报告。

不得为在线验证修改用户真实配置、交易环境或生产缓存。清理、sandbox=0、并发和错误注入的证据全部来自离线临时库；外部只读不妨碍隔离测试库按路由自然写入。

交付只报告实际检查范围、结果和剩余限制，主任务/子任务文档不记录本次次数、耗时、进度或 commit hash。满足预定范围后停止，不额外开展全项目交易功能改造或分布式运维建设。
