# 配置场景与部署规范统一

## 使用场景与设计初衷

开发和本地生产使用直连代理配置及本机 CFB；远程生产需要三个代理开关开启，并通过容器名访问 CFB。过去上传脚本修改配置副本，配置加载器无法解释场景差异。本地生产也复制配置快照，源码每次完整上传，与新规范不一致。公共时间独立 HTTPX 请求未读取币安代理配置，会出现交易行情正常、取时因出口限制失败的问题。

## 方案对比

继续增加上传补丁会让配置解释分散在部署端和应用端。场景覆盖将最终值统一交给加载器，上传仅传输原文件。全量源码归档校验可靠但重复传输较大依赖；文件清单与摘要差异传输保留完整性证明并减少重复上传。

## 取舍结论

采用唯一配置场景加载链和带完整清单的增量同步。保留既有 Just 名称、远端无宿主 Python、互斥与停止代次、失败保护和定向清理。vnpy_ctp 继续由镜像依赖阶段编译并内置，暂不引入预编译交付链。

公共取时统一调用 CCXT fetch_time 并复用币安代理配置。使用独立异步客户端保持取时不依赖交易实例初始化，严格响应验证避免 SDK 类型转换弱化原有契约。取时交付只验证本地构建镜像，不上传或启用远端版本。
