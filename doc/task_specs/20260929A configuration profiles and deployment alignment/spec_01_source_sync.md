# 源码增量同步

## 输入与清单

保留原构建白名单：Dockerfile、.dockerignore、pyproject.toml、uv.lock、src 的 Python/约定 JSON、CTP vendor 构建资料及三个后台运行脚本。拒绝符号链接、路径穿越、重复路径和非白名单文件，不传开发缓存、配置、数据库或历史。

source.manifest 使用排序后的 SHA256 清单，每行 `64位小写摘要␠␠相对路径`，文件名限原白名单安全字符。清单列出完整版本，包含全部必需输入；其 SHA256 为版本身份。空源码版本非法。

上传先读取 inventory：第一行为已提交源码身份或 none，后续为现有文件实际内容摘要。远端清单缺失时返回空文件集合；旧全文归档按空文件集合引导首次完整上传。读取在短操作锁中进行，缺失文件不虚构命中；不输出配置内容。

本机冻结本次文件内容，按实际摘要选择变化文件，形成 source.delta.tar.gz，同时上传 source.manifest、source.base。没有变化时 delta 可为空。配置仍按既定完整上传/保留规则单独处理，控制脚本作为部署协议输入发送。

## 原子提交

远端在现有操作锁内检查 source.base 是否仍等于当前已提交身份；不一致直接拒绝，提示重新上传，不混合两个发布者的版本。

在 .container 的临时目录中复制现有受管源码；只依据新旧合法清单删除不再需要的源码文件，覆盖 delta 后核对完整文件集合、类型和逐文件摘要。任何缺失、额外文件、链接、错误摘要或不匹配的 patch 均拒绝。配置和业务数据不位于此目录。

完成后发布到 `.container/sources/<清单摘要>/`，内部为 `files/` 和 `manifest`；更新两行 uploaded 元数据：源码身份、配置快照身份。失败不更新 uploaded、prepared 或运行实例；临时目录清理。

build 重新验证已提交树的完整集合与摘要，再用它构建，不消费在途目录。配置仍在源码树之外。完整构建及配置预检后才更新 prepared。

## 清理和迁移

仅保留 uploaded 引用的源码版本；清理范围限定受管 sources 下的合法摘要目录及旧格式摘要归档。当前运行镜像、配置快照、共享构建缓存、数据库继续遵守既有保护。

新协议直接取代整包上传，不保留两套正常发送路径。尚未重新上传的旧源码格式不能被新 build 默默接收；配置保留选项可沿用旧 uploaded/prepared 中的完整配置快照，不需要远端宿主 Python 或新增同步服务。
