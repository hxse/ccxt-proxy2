# 换月过渡窗口

## 使用场景与设计初衷

主连从旧合约切换到新合约后，用户希望同时取得旧合约在换月后对应周期前 N 根的真实价格，用于本地换月分析。原始主连保持官方价格，不复权、平滑或拼改。

默认 N=10，但用户可依次请求 5、3、10 根。缓存应复用最长已经完整确认的窗口，避免重复存前缀或被短请求覆盖。

## 方案对比

把旧合约一万根全落盘会保存大量与需求无关的数据。只提取目标窗口既节省空间，又能明确证明数据来自单次 SDK 结果。

普通片段可由多批重叠形成，不能据同一个 segment_id 证明本次 N＋1 根来自同一次调用。因此保留共同尾根筛选，另设严格的整窗提交入口。

## 取舍结论

映射与价格分开保存，在同一路由按节点组合。目标 N＋1 根完整提交，缓存统一排除末根，原子保存 N；不足时可响应但不写任何过渡价格。
