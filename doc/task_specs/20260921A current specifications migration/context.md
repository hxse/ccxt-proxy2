# 现行规范文档迁移

## 使用场景与设计初衷

项目已经采用 AGENTS.md 的文档与 JJ 规范。原 docs 同时存放当前实现约定、早期迁移步骤、交易所研究和已否决设计，文件名与状态标签仍带有旧设计阶段的语义。使用者需要按模块直接找到现行约定，避免将历史方案当作开发要求。

## 方案对比

仅更换目录名会把历史设想一起带入 current spec，也会保留已经结束的实施步骤。按内容职责迁移则可以保留当前模块的完整规则，同时把只承担历史背景的材料放入独立归档位置。

## 取舍结论

采用按职责迁移：有效规范按模块放入 doc/current_specs，历史材料保存在 doc/archive，入口和引用同步调整。核对相关源码只用于辨别现行行为；发现需要改变程序契约的问题时不借文档迁移实施。以前的提交保持原样，本次工作使用独立的正式 task change。
