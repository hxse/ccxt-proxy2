# 现行规范文档迁移

## 任务边界

迁移现有 docs 中的有效架构、配置、接口、生命周期、缓存、错误和验证约束至 doc/current_specs。同步 README 及受影响 Markdown 的路径引用。研究记录、已否决设计和已完成的迁移过程归档至 doc/archive，保留有独立价值的历史内容。

本任务只修改文档；不修改业务源码、测试、依赖、账号配置、AGENTS.md 或旧提交，不调用交易服务。达到内容归属清楚、现行约束无遗漏、引用有效及手写文档行数符合规范即可交付。

## 任务规范

- current spec 按模块组织，采用英文文件名、中文正文与章节标题。总览负责说明当前正式链路和模块边界，不维护任务进度或手工任务索引。
- 已实现且仍有效的规则由 current spec 承担；研究样本、已否决机制和尚未实现的设想不得成为当前实现要求。已结束的迁移步骤与一次性验收记录不进入现行规范。
- 每条核心规则只完整定义一次。公共配置、服务白名单和生命周期集中描述；各模块通过引用说明共同规则，保留其独有配置及行为。
- 迁移前阅读原文，沿涉及的配置、路由和实现入口核对行为。源码与约定冲突应明确说明，不能默默将实现缺陷改写为规范；改变算法或接口不属于本任务。
- 历史文档保留原有事实与边界，仅调整归档位置、权威说明和失效的路径引用。超长的现行文档按职责整理或拆分，其他手写文档不超过 400 行。
- 本次任务保持 meta、context、spec 三份文档，不增加执行报告、审阅报告或任务状态文件。

## 公开接口与用户写法

程序的 HTTP、CLI、配置和返回结构保持原样。用户从根 README 进入 doc/current_specs/architecture.md，再按模块查阅具体约定。正式规范中保留真实请求、配置与返回示例；将未实现方案标为历史，不让调用方误认为当前支持。

文档中的生产命令、测试命令和 Bruno 用法以仓库现有入口为准。当前任务说明不替代各模块的现行规范，历史材料不作为理解当前接口的必要前置。

## 测试、验证与阶段过渡

纯文档迁移只核对内容、源码对应关系、示例逻辑、引用、文件行数和 JJ 差异，不运行构建、测试、lint、类型检查或网络探针。检查迁移后没有指向旧位置的现行引用，不丢失仍有效的独有规则，不把历史设计混入 current spec。

本任务内完成新位置与引用切换，不保留另一套现行文档副本。归档是历史资料的唯一保留位置；原有业务文件与配置须保持不变。JJ 变更仅包含文档及其必要引用调整，不改写上游 change，不推送远端。
