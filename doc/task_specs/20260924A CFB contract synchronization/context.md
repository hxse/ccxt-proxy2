# CFB 上游契约同步

## 使用场景与设计初衷

cn-futures-bridge 更新了订单完整引用查询、提交与核验结果、一致性字段及运行模式说明。代理仍公开相同的八条业务路由，但旧 OpenAPI 快照未体现新增参数和响应结构，调用方无法从本项目文档找到完整的订单复查方式。

本任务作为当前开发栈的独立子 change，承接既有代码与文档状态，不归入此前的文档迁移任务。

## 方案对比

现有代理原样转发查询字符串、请求体和响应，能够承载新增字段。使用既有同步入口刷新快照，并更新调用示例与针对性回归，可以保持上游为业务契约的唯一来源。

在代理新增订单模型、校验或结果裁剪，会形成第二套业务规则，并妨碍上游后续字段扩展；动态公开全部上游路径也会扩大既有业务入口边界。

## 取舍结论

沿用固定八条业务路由及原始字节转发，使用上游 OpenAPI 更新自动文档。模式匹配、订单关联、成交核验和错误判断继续由 CFB 实现。代理只保留自身鉴权、白名单和网络错误契约。
