# 委托价格精度与边界

## 使用场景与设计初衷

前端用 K 线开盘价乘以报价系数，再提交限价。该计算可能产生非合法步长价格，也可能超过交易所当前允许范围。调用方不应维护各交易所的规则。

当前 CCXT 会四舍五入价格，CTP 原价提交并等待拒单。Binance 的具体价格拒绝原因还会被压缩成笼统参数错误。需要统一后端职责，同时让调用方知道实际委托价格。

## 方案对比

完全由前端处理会重复交易所规则。把所有价格强制截入合法区间则可能改变委托预期。后端按买卖方向对齐步长、明确拒绝越界报价，可以保留调用方价格界限，并继续让交易所作最终判断。

## 取舍结论

报价买入向下、卖出向上对齐；触发价格是另一种语义，严格校验而不自动移动。使用同一交易环境的官方资料，拒绝猜测步长或借用其他环境行情。交易所动态风控仍可能在本地预检后拒单，应保留可安全公开的错误原因。

CFB 的独立上游负责自身规则，本任务不修改其薄转发或上游实现。原生市价、成交等待方式和订单有效期策略不属于本任务。
