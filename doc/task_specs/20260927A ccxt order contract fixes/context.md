# CCXT 订单请求与回执修复

## 使用场景与设计初衷

调用方请求 IOC/FOK 限价时，希望未立即满足的数量取消；当前锁定的 CCXT 4.5.76 没有正确编码 Kraken Futures 的大写 timeInForce，可能把请求变成普通挂单。部分合法订单查询、条件单撤单回执不包含 type/side，现有 HTTP 响应模型会丢失这些成功回执。amount/leverage 的布尔值又会先被模型转换为数字，绕过客户端拒绝布尔值的校验。

旧价格任务明确不处理订单有效期及无关回执问题，故本次单独修复这三个交易契约缺陷。

## 方案对比

升级整个 SDK 会引入与本次无关的行为变化；在现有客户端按交易所适配有效期，结合真实 SDK 最终请求回归，边界更明确。未知回执字段设为 null 可以保留事实，猜测类型或追加查询会改变语义和请求次数。数值转换前拒绝 bool 可以保留已有合法数字字符串写法，无需把所有字段改为严格类型。

## 取舍结论

保持路由、交易环境默认值、价格步长/边界、数量精度和写操作不重试的规则；只修复已声明的有效期、未知字段和非法布尔输入。全部验证离线运行真实 SDK 编解码并拦截网络，不用真实委托验证。
