# 行情数据的证据与职责

本文集中定义当前行情链路的术语与职责。具体接口、参数和算法分别以 [CCXT OHLCV](ccxt_ohlcv.md)、[TQ 行情](tq_data.md)及缓存三篇为准；未实施的设计属于 task spec。

## 三种不同的保证

| 保证 | 证据 | 不能替代它的现象 |
| --- | --- | --- |
| 本次查询完整 | Provider 能力、分页连接、边界与预算检查 | HTTP 200、结果非空、时间看起来接近 |
| 缓存片段可连续复用 | 合法完整批次以及批次间实际时间戳交集 | 片段编号大小、时间范围相交、固定时间差 |
| 某根可持久化 | 同一已验证序列里存在严格更晚的一根，或已经是可信缓存行 | 本机时间、交易日历、休市状态、重复同时间戳 |

完整查询允许按接口契约返回短历史；它不意味着总能得到用户请求的数量。合法短结果、上游失败和中途部分结果不能混为一谈。

项目重点维护上市后的正常数据。上市前相关请求，现有链路能直接处理就处理，处理不了就按对应错误明确结束；不为此新增上市日期查询、历史起点探测或跨空窗口补拉。正常取得的合法短数据继续按现行接口返回，不承诺所有 Provider 的上市前边界都成功。已有覆盖证明保留，不为扩大上市前覆盖额外请求。

当前 CCXT 完整查询以 OhlcvResult 描述结果与尾根资格。当前 TQ 普通行情是 SDK 实时窗口，不接项目磁盘缓存，也没有 CCXT 的完成性响应字段。

## 获取、存储与返回

获取层负责 Provider 参数、分页和有效结果；缓存只消费已成立的证据，负责持久化筛选、片段连接、修订与事务。HTTP 路由不操作缓存底层表，不自行更改 segment_id 或 covered_from。

尾根返回与落盘相互独立。CCXT 响应保留目标窗口，缓存根据完成证据选择可保存行；数据库读出的末行已可信，不因它是响应最后一行再去尾。CCXT 三种普通查询都取消专门后继确认，网络目标末根只返回不新增落盘；纯缓存末根保持可信，具体流程见 [查询算法](ohlcv_cache_resolution.md)。

segment_id 是逻辑关系，不是单次请求编号。一个片段可由多个完整批次通过重叠合并形成；同一片段不自动证明所有行来自一次 Provider 调用。

covered_from 表示已证明的查询下界，first_time 表示实际首行，两者不可互换。裁掉前缀后必须维护覆盖证明，不能把被删除的旧数据说成原本不存在。

当前普通写入会执行 upsert；时间戳已经存在不代表可以跳过更新，因为同批数据可能桥接片段、修订价格或扩大覆盖。网络缺少某条旧记录也不自动授权删除它。

## 时间与数据域

当前 CCXT OHLCV 和缓存 time 使用整数 Unix 毫秒，TQ datetime 使用整数 Unix 纳秒，日历 date 表示中国期货自然日。代码与示例必须明确单位，不能通过浮点转换丢失精度，也不能把自然日期当作 UTC 零点时刻。

缓存不使用 interval 推断连接。当前 CCXT 完整分页对固定周期检查相邻时间戳；LatestLimit 以一次固定 S 配合 interval 计算起点，再复用相同 S 的内部查询。向后续页仍从真实末端含首请求，不使用 tail＋interval 代替重叠点。

TQ 的 duration_seconds 只指定 SDK 周期，休盘、周末和节假日不能被固定时间差判成缺失。日历通过标准日期运算检查逐自然日齐全，与用 K 线周期推算行情连续性是两种行为。

## 开关、状态与错误

当前 CCXT 三类 OHLCV 默认 enable_cache=true，false 同时禁止项目缓存读取与写入。当前 TQ 未声明该参数，未知参数按原规则拒绝，不能将未来计划写成当前开关。

TQ 交易状态的 null 表示未知；没有推送、不再变化或 HTTP 成功都不能证明休市。当前行情请求不根据状态切换为磁盘缓存返回。

普通缓存读写错误与容量保护错误分别处理，规则见 [缓存操作](ohlcv_cache_operations.md)。完整网络失败不能通过部分持久化或成功短响应掩盖。

## 数量与磁盘

CCXT 单次响应上限、单序列缓存容量与全库容量分别约束不同对象。逻辑行数不等于精确磁盘字节数，数据库空闲块还可以被后续写入复用。

保留正常 WAL 和自动 checkpoint；它们服务于持久性与空间管理，不是长期行情备份。文件未立即变小不表示删除无效，额外空闲空间预算也不是已经占用的空间。当前没有周期保留清理路由或自动整库压缩流程。
